## 1. ISM — מוניטור בטיחות עצמאי

**חומרה:** STM32H7 (מיקרו-בקר ייעודי)
**תקינה:** High Integrity — MIL-STD-882E
**עיקרון:** ISM הוא **מחסום הבטיחות האחרון** — פועל באופן עצמאי לחלוטין

### תפקידים

| # | תפקיד | פירוט |
|---|-------|-------|
| 1 | **SAFE בעלייה לחשמל** | קו disable-torque מופעל ב-T+5ms מרגע הפעלת החשמל |
| 2 | **ניטור heartbeat** | אם FCC לא שולח heartbeat תוך 500ms → FAULT |
| 3 | **ניהול state machine** | SAFE / STANDBY / ARMED / FIRING / FAULT |
| 4 | **אישור STANDBY** | מקבל רק ממצב SAFE |
| 5 | **אישור ARM** | מקבל רק ממצב STANDBY |
| 6 | **הפעלת torque** | מאשר הפעלת מנוע רק לאחר ARM תקין |
| 7 | **אימות פקודות תנועה** | בדיקת טווח (±180° az, ±90° el), קצב (≤45 dps), מצב נוכחי |
| 8 | **דחיית פקודות לא חוקיות** | כל פקודה לא חוקית → FAULT מיידי |
| 9 | **אישור ירי** | דורש אינטרלוק דו-ערוצי (ערוץ A **וגם** ערוץ B) |
| 10 | **ניתוק torque מיידי** | בכל מצב FAULT / SAFE — ניתוק חומרתי בלי תלות בתוכנה |
| 11 | **רישום תקלות** | כל תקלה נרשמת עם: זמן, מצב, מקור, סיבה |
| 12 | **נוהל התאוששות מבוקר** | מ-FAULT ל-SAFE דורש: ניקוי תקלה + אישור גורם מוסמך |
| 13 | **Watchdog חומרתי** | IWDG עצמאי — אם ISM עצמו תקוע → reset אוטומטי → SAFE |

### מה ISM **לא** עושה

| ✗ | סיבה |
|---|------|
| לא קורא encoder מנוע | תפקיד FCC — לא קריטי לבטיחות |
| לא מחשב מסלול / PID | תפקיד Medium Integrity — שייך ל-FCC |
| לא מתקשר עם פאנל / WebApp | תוכנה לא-בטיחותית לא נוגעת ב-ISM |
| לא מזרים וידאו | תפקיד לא-בטיחותי |
| לא רץ על Linux / Jetson | Linux אינו דטרמיניסטי, לא ניתן לסרטיפיקציה |

### ממשקי ISM

| ממשק | פרוטוקול | תוכן |
|------|----------|------|
| FCC ↔ ISM | CAN bus | פקודות, אישורים, דוחות תקלה |
| ISM → מנועים | CAN + קו חומרתי | torque enable/disable |
| ISM → חומרת ירי | CAN | fire enable/inhibit |

## 2. FCC — מחשב שליטת אש

**חומרה:** NVIDIA Jetson Orin NX
**תקינה:** Medium Integrity — MIL-STD-882E
**עיקרון:** FCC הוא **גשר** בין העולם החיצוני לבין ה-ISM

### תפקידים

| # | תפקיד | פירוט |
|---|-------|-------|
| 1 | **שליחת heartbeat ל-ISM** | כל 100ms דרך CAN |
| 2 | **קריאת encoder מנוע** | קריאת מיקום az/el נוכחי מ-CAN |
| 3 | **חישוב פקודת תנועה** | PID / trajectory מ-encoder + יעד מהמפעיל |
| 4 | **שליחת פקודת תנועה ל-ISM** | ISM מאמת ומאשר |
| 5 | **קבלת stream מ-Micro300** | H.265 דרך Ethernet / RTSP |
| 6 | **שליטה על גימבל** | פקודות pan/tilt/zoom דרך MavLink |
| 7 | **העברת וידאו ל-GCS** | RTP/UDP stream |
| 8 | **שרת HTTP ל-WebApp** | REST API — מקבל פקודות מפאנל ומעביר ל-ISM |
| 9 | **שדר telemetry ל-GCS** | JSON עם מצב מערכת, az/el, מצלמה |
| 10 | **רישום אירועים** | לוג מפורט לצורך SAR evidence |

### מה FCC **לא** עושה

| ✗ | סיבה |
|---|------|
| לא מפעיל actuators ישירות | ISM שומר על torque gating — SWR-SAFE-002 |
| לא אוכף גבולות בטיחות | אחריות ה-ISM בלבד |
| לא עוקף את ה-ISM | כל פקודת תנועה חייבת לעבור אימות ISM |
| לא מריץ watchdog | ל-ISM יש watchdog עצמאי משלו |

### ממשקי FCC

| ממשק | פרוטוקול | תוכן |
|------|----------|------|
| FCC ↔ ISM | CAN bus | heartbeat, פקודות, state ack |
| FCC ← Encoder | CAN 0x300 | מיקום az/el נוכחי |
| FCC → Motor driver | CAN 0x301 | פקודת מהירות |
| FCC ↔ Micro300 | Ethernet | H.265 RTSP + MavLink UDP |
| FCC ↔ GCS | RF / UDP | telemetry + video |
| FCC ↔ WebApp | HTTP REST :5300 | פקודות מפאנל |

## 3. פאנל מפעיל / GCS WebApp

**פלטפורמה:** דפדפן (Blazor) על מחשב תחנת קרקע
**תקינה:** Low Integrity — MIL-STD-882E
**עיקרון:** הפאנל **מציג ושולח בקשות בלבד** — לא קובע מדיניות בטיחות

### תפקידים

| # | תפקיד | פירוט |
|---|-------|-------|
| 1 | **הצגת מצב המערכת** | SAFE / STANDBY / ARMED / FAULT בצורה ברורה |
| 2 | **הצגת telemetry** | az/el נוכחי, מהירות, torque on/off |
| 3 | **הצגת מצב מצלמה** | stream פעיל/כבוי, frames, zoom |
| 4 | **שליחת STANDBY** | לחצן מפעיל → POST /api/standby → FCC → ISM |
| 5 | **שליחת ARM** | לחצן ARM → POST /api/arm → FCC → ISM |
| 6 | **שליחת DISARM / SAFE חירום** | לחצן בולט → POST /api/disarm → FCC → ISM |
| 7 | **שליחת יעד תנועה** | az/el/rate → POST /api/move → FCC → מנוע |
| 8 | **שליחת פקודות גימבל** | pan/tilt/zoom → POST /api/gimbal → FCC → Micro300 |
| 9 | **אישור כפול לירי** | שני לחצנים נפרדים לאישור → POST /api/fire → FCC → ISM |
| 10 | **בקשת התאוששות** | אחרי FAULT → אישור מפעיל → POST /api/recovery |

### מה הפאנל **לא** עושה

| ✗ | סיבה |
|---|------|
| לא מדבר עם ISM ישירות | ISM קריטי לבטיחות — כל פקודה דרך FCC בלבד |
| לא מדבר עם Micro300 ישירות | ממשק המצלמה הוא באחריות FCC |
| לא אוכף בטיחות | הבטיחות היא אחריות ISM בלבד |
| לא מניח מצב ISM | תמיד קורא status מ-FCC — לא מנחש |
| לא מחזיק state פנימי | המצב האמיתי נמצא ב-ISM, לא בפאנל |

### ממשקי פאנל

| ממשק | פרוטוקול | תוכן |
|------|----------|------|
| WebApp → FCC | HTTP POST :5300 | פקודות מפעיל |
| WebApp ← FCC | HTTP GET :5300 | status JSON |

## 4. זרימת פקודה — דוגמה מלאה

```
מפעיל לוחץ ARM
       │
       ▼
  WebApp (Low)
  POST /api/arm
       │ HTTP
       ▼
  FCC (Medium)
  מאמת שיש heartbeat תקין עם ISM
  בונה CAN frame 0x101
       │ CAN
       ▼
  ISM (High)
  בודק: האם מצב = STANDBY?
  כן → מעביר ל-ARMED
      → מפעיל torque
      → שולח STATE_ACK
       │ CAN
       ▼
  FCC מקבל ACK
  מעדכן status
       │ HTTP
       ▼
  WebApp מציג: ARMED 🟠
```
